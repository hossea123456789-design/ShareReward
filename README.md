# 보스 정산 공유 웹앱 v5.0

## v5 핵심 변경

v5는 기존의 `판매대기 → 판매 완료 → 정산중 → 지급 완료` 흐름을 `정산 등록 → 묶음 선택 → 정산 완료`로 단순화한 버전입니다.

### 1. 억당 시세 실시간 반영
- 정산대기 상태의 현금 환산액은 설정의 **현재 억당 시세**를 실시간으로 사용합니다.
- 정산을 등록한 뒤 시세를 바꿔도 대기 건의 원화 정산액이 즉시 바뀝니다.
- **정산 완료 시점**의 시세는 해당 완료 기록에 고정되어 이후 설정값을 바꿔도 과거 완료 금액은 유지됩니다.
- 기존 v4 완료 기록은 기존 `sale.cashRatePerBillion` 값을 우선 사용합니다.

### 2. 묶음 정산
1. `+ 정산 등록`에서 날짜, 보스, 파티/참여자, 아이템, 판매가를 입력합니다.
2. 새로 등록한 정산은 자동으로 `정산대기` 목록에서 선택됩니다.
3. 여러 건을 연속 등록하면 선택 상태가 누적됩니다.
4. 필요하면 체크박스로 선택/해제하거나 `전체 선택`, `선택 해제`를 사용합니다.
5. `선택 N건 정산 완료`를 누르면 선택된 모든 정산이 동시에 완료됩니다.
6. 완료 직후 선택한 건 전체를 합친 공유 문장이 생성됩니다.

### 3. 공유 문장 축약
단일 정산 예시:

```text
정산 날짜: 2026.09.20
정산 인원: 2인

세렌 · 신념의 연마석
정산 금액: 20.85억 / 37,530원
```

여러 건 동시 정산 예시:

```text
정산 날짜: 2026.09.20
정산 인원: 2인

세렌 · 신념의 연마석
정산 금액: 20.85억 / 37,530원

노말 칼로스 · 생명의 연마석
정산 금액: 4.84억 / 8,712원

총합: 25.69억 / 46,242원
```

날짜나 참여자 구성이 다른 정산을 동시에 완료하면 같은 공유문 안에서 그룹별로 나뉘어 표시됩니다.

## 화면 구조

- 홈
- 정산대기
- 정산완료
- 설정

기존 `정산중` 탭은 제거했습니다. 기존 데이터의 `waiting`, `settling` 상태는 둘 다 정산대기로 취급하며, `done` 기록은 그대로 유지합니다.

## 계산 기준

```text
수수료 = 판매가 × 수수료율
최종 정산금액 = 판매가 - 수수료 - 정산 제외 금액
1인당 메소 = 최종 정산금액 ÷ 참여자 수
1인당 현금 = 1인당 메소 × 억당 현금가
```

새 정산은 설정의 수수료/반올림 규칙을 기준으로 생성합니다. 기존 정산에 저장된 수수료/반올림 값이 있으면 해당 값을 유지합니다.

## 공유 저장소

현재 구조는 기존과 동일합니다.

- 프런트: GitHub Pages
- 공유 데이터: Google Sheets
- API: Google Apps Script
- 기본 Apps Script URL은 기존 설정을 유지합니다.

v5에서 추가되는 완료 시세 정보는 기존 `saleJson` 내부에 저장되므로 별도의 시트 열 추가 없이 동작하도록 구성했습니다.

## 기존 데이터 호환

- v4의 `waiting` → v5 정산대기
- v4의 `settling` → v5 정산대기
- v4의 `done` → v5 정산완료
- 기존 판매가/수수료/반올림/제외금액 정보는 최대한 유지
- 대기 건의 현금 환산은 v5부터 최신 설정 시세 사용
- 완료 건의 현금 환산은 완료 시점 시세 고정

## 주의

- 공유 저장은 기존과 동일하게 마지막 저장 내용이 기준입니다.
- 여러 사용자가 동시에 같은 기록을 수정하면 나중에 저장한 내용이 남을 수 있습니다.
- Apps Script 백엔드는 현재 저장 구조를 그대로 사용하는 전제로 설계했습니다.
